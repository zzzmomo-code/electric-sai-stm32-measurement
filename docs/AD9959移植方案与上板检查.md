# AD9959 双通道双向移植方案与上板检查

## 1. 最终方案

目标工程为 `dds2`，MCU 为 STM32H743VIT6，开发环境为 STM32CubeIDE 1.19.0。
保留原 SPI2 上的第一块 AD9834；删除第二块 AD9834 的 `ad9834_2.c/.h`、SPI6 和
PB3/PB5/PD6/PD7 的旧功能。AD9959 改用 SPI4：

- AD9959 单比特三线串行模式；
- STM32 SPI4 全双工硬件主机，SDIO_0 写、SDIO_2 读；
- CH0、CH1 输出，CH2、CH3 数字核和 DAC 关闭；
- 每次改频率、相位或幅度后产生 IO_UPDATE，并回读目标寄存器；
- 无 DMA、无 SPI 中断，先以简单、可观察、易排错为优先。

这里的“单比特三线串行模式”是 AD9959 数据手册的命名：时钟 SCLK、输入
SDIO_0、输出 SDIO_2；CS 仍单独存在。它不是把 MOSI/MISO 并到一根双向线上。

选择这个方案的原因：

1. SPI4 的 PE2/PE5/PE6 在当前 H743VI IOC 中可用，不需要改动现有 SPI2、SPI3。
2. 硬件 SPI 比逐位 GPIO 模拟更短、更容易用逻辑分析仪确认，也保留稳定回读能力。
3. 指令与数据一次性发送，规避失败工程中 CS 低期间拆成多次 HAL 调用的问题。
4. 只开放 CH0、CH1 API，减少误选通道；CH2、CH3 仍在初始化和回读中被明确验证为关闭。

## 3. 可行性结论

AD9959 数字接口可与 3.3 V STM32 直接通信。当前模块使用 5 V 供电，板上产生芯片需要
的 1.8 V 和 3.3 V 电源；模块资料要求电源具备约 1 A 余量并与 MCU 共地。模块带
25 MHz 振荡器，FR1 配置 PLL×20 后系统时钟为 500 MHz。

本工程 SPI45 内核时钟为 120 MHz，SPI4 预分频 8，SCLK 为 15 MHz，远低于 AD9959
串行口上限。H743 数据手册给出的 3.3 V、30～50 pF 条件下 Low speed GPIO 上限约
12 MHz，因此 SPI4 三根复用引脚使用 Medium speed，既覆盖 15 MHz，又避免无必要的
最高摆率。

模块输出端带约 200 MHz 低通网络；驱动将软件可设上限限制为 200 MHz。初次上板只用
1 MHz，先验证数字链路和基本模拟输出，不直接从高频开始。

## 4. 硬件连接

| STM32H743VI | AD9959 模块 | 方向 | 说明 |
|---|---|---|---|
| PE2 / SPI4_SCK | SCLK | STM32→AD9959 | Mode 0，15 MHz |
| PE6 / SPI4_MOSI | SDIO_0 | STM32→AD9959 | 指令和写数据 |
| PE5 / SPI4_MISO | SDIO_2 | AD9959→STM32 | 寄存器读回 |
| PD5 / GPIO | CS | STM32→AD9959 | 低有效，空闲高 |
| PD4 / GPIO | IO_UPDATE | STM32→AD9959 | 高脉冲，驱动保持 2 µs |
| PB4 / GPIO | RESET | STM32→AD9959 | 高有效 |
| GND | GND | 共地 | 必须连接 |
| 独立 5 V 电源 | 5V/VCC | 供电 | 建议至少 1 A 余量 |

模块端固定连接：

- `PDC` 直接接 GND，不能悬空；
- `SDIO_3/SYNC_I/O` 直接接 GND；
- `P0`、`P1`、`P2`、`P3` 直接接 GND；
- `SDIO_1` 不连接；
- 只使用 CH0、CH1 输出，CH2、CH3 不连接。

PB4 复用了 NJTRST。当前 SYS Debug 采用 Serial Wire，未使用完整 JTAG，因此 PB4 可作
普通 GPIO；如果以后改回 JTAG，必须重新处理这个冲突。

布线建议：

- 六根数字线和地尽量短，优先使用相邻地线，不要用长而松散的杜邦线；
- 模块 5 V 电源不要从逻辑 IO 取电；
- 第一次看波形时示波器使用 1 MΩ 输入。模块输出网络已有阻抗元件，直接再开 50 Ω
  端接会改变幅度，必须在明确负载模型后再使用；
- 逻辑分析仪夹在模块排针处，而不只夹在 MCU 端，以便发现接线和接触问题。

## 6. 驱动初始化与寄存器期望值

`system_init()` 调用 `ad9959_init()`，顺序如下：

1. CS 拉高、IO_UPDATE 拉低，RESET 高脉冲复位；
2. 写 CSR=`F2`，选择全部通道并切换单比特三线串行模式；
3. 写 FR1=`D0 00 00`，启用 25 MHz×20 PLL；
4. 产生 2 µs IO_UPDATE，并等待 5 ms；
5. 写 FR2=`00 00`；
6. 对 CH0、CH1 分别写：
   - CSR：CH0=`12`，CH1=`22`
   - CFR=`00 03 02`
   - FTW0=`00 83 12 6F`，对应 1 MHz
   - CPOW0=`00 00`
   - ACR=`00 13 FF`，手动幅度满量程 1023
7. 对 CH2、CH3 分别写 CFR=`00 03 C2`，关闭数字核和 DAC；
8. 再次 IO_UPDATE；
9. 逐通道回读 FR1、FR2、CFR、FTW、CPOW、ACR，最后恢复选择 CH0。

CSR 中的三线模式位必须在以后每次选择通道时保留，所以四个通道选择值固定为
`12`、`22`、`42`、`82`。不能退回只写 `10`、`20`、`40`、`80`。

写帧使用一次 `HAL_SPI_Transmit()` 发送“指令+全部数据”；读帧使用一次
`HAL_SPI_TransmitReceive()` 发送“读指令+占位字节”并接收全部返回值。CS 在整个 HAL
调用期间保持低，不能把指令和数据拆成两次 HAL 调用。

## 7. H743 SPI 勘误处理

当前 ST ES0392 Rev. 15 中与此驱动直接相关的项目：

- 2.22.2：一次传输结束后过快发起新的 CSTART 可能停住。驱动在每个完整帧前后留
  1 µs 间隔。
- 2.22.5：CRC 关闭且 CRC size 小于 8 位时，最后接收数据可能损坏。当前数据宽度和
  CRCSIZE 均为 8 位。
- 2.22.6：EOT 后立即关闭 SPI 可能截短最后一个 SCK 脉冲。H7 HAL 会在传输收尾关闭
  SPI，因此配置采用较低的 PCLK:SCK 比值 8、开启 Master Keep IO State，并把一帧
  合并为一次 HAL 调用，避免中间 EOT。最终仍需用逻辑分析仪确认最后一个时钟完整。

这些处理降低了勘误风险，但不能代替实板时序测量。

## 9. 失败工程排查结论

`h743_pre1` 的历史版本先后出现过 SPI4 位宽/速率反复变化、一次 CS 低电平内把指令和
数据拆成多个 HAL 事务，以及最终改成大体量 GPIO 模拟 SPI 的情况。早期 IO_UPDATE
高电平仅有很短的 NOP 延时，也不适合作为可靠的首次 25 MHz 参考时钟条件。

原实测“约 50 MHz、3 mV、半个正弦”更像没有得到有效 DAC 输出时看到的时钟串扰或
噪声，但仅凭这个波形不能证明唯一根因。因此新工程没有复制失败驱动，而是从数据手册
寄存器约束重新建立：

- 8 位 Mode 0 硬件 SPI；
- 完整帧单 HAL 事务；
- 2 µs IO_UPDATE；
- 先 PLL 再配置通道；
- 每次写后回读；
- 明确关闭 CH2/CH3；
- 逻辑分析仪和示波器分阶段验收。

- [ ] IO_UPDATE 高电平约 2 µs。
- [ ] 读操作时 PE5 有返回数据，最后一个 SCLK 脉冲完整。

### 阶段 D：调试器回读

- [ ] `initialized == 1`
- [ ] `verified == 1`
- [ ] `readback_mismatch_mask == 0`
- [ ] `last_status == ad9959_status_ok`
- [ ] `fr1_readback == D0 00 00`
- [ ] `fr2_readback == 00 00`
- [ ] CH0/CH1 `cfr_readback == 00 03 02`
- [ ] CH0/CH1 `ftw_readback == 00 83 12 6F`
- [ ] CH0/CH1 `cpow_readback == 00 00`
- [ ] CH0/CH1 `acr_readback == 00 13 FF`
- [ ] CH2/CH3 `cfr_readback == 00 03 C2`

### 阶段 E：模拟输出

- [ ] CH0、CH1 均为 1 MHz。
- [ ] CH2、CH3 无有效输出。
- [ ] 把 CH1 改为 2 MHz 后，频率和 FTW 回读同时变化。

## 11. 锁相边界

AD9959 的 SPI 回读只返回配置寄存器。FTW 和 CPOW 回读正确说明“写入的目标值正确”，
不说明当前相位累加器值，也不说明 SMA 端的真实模拟相位。

后续做真正锁相，需要增加至少一种反馈：

- 第二路 ADC 同步采样 AD9959 输出；
- 外部鉴相器/混频器输出接 ADC；
- 其他能观测真实模拟相位误差的硬件。

ADC 采样、相位误差计算和所有 DDS IO_UPDATE 必须共享一个确定时基。仅靠 SPI 回读
闭环属于配置闭环，不是模拟输出相位闭环。
