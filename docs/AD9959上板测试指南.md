### 0.3 接线表

按 README.md "硬件连接" 章节接线，重点确认 AD9959 部分。

**模块供电（关键！）**

| 模块引脚 | 接 | 说明 |
|---|---|---|
| DC 供电座 5V | 外部 5V 1A 电源 | 模块只接 5V 单电源，板载 LDO 自动降到 1.8V/3.3V |
| GND | STM32 GND | **必须共地** |

⚠️ **不要**再额外接 1.8V 或 3.3V 给模块（除非你确认模块版本需要双电源）。康威科技 KV-AD9959 是单 5V 输入设计。

**STM32 信号线（本项目实际接法）**

| MCU 引脚 | AD9959 模块丝印 | 芯片引脚名 | 备注 |
|---|---|---|---|
| PE2 | SCLK | SCLK | SPI4 时钟 |
| PE6 | SD0 | SDIO_0 | MOSI（写） |
| PE5 | SD2 | SDIO_2 | MISO（读回） |
| PD4 | UPDATE | I/O_UPDATE | 上升沿刷新寄存器 |
| PD5 | CS | CS | 片选，低有效 |
| PB4 | RST | MASTER_RESET | 硬件复位，高有效 |
| GND | PDC | PWR_DWN_CTL | 必须拉低，禁止芯片进入外部掉电状态 |
| GND | SD3 | SDIO_3 / SYNC_I/O | 单位串行模式下固定为逻辑0，禁止浮空 |
| GND | P0, P1, P2, P3 | profile输入 | 单音模式固定为逻辑0，避免数字输入悬空 |
| GND | GND | GND | 共地 |

**模块其他引脚**

| 模块丝印 | 芯片引脚名 | 处理 | 原因 |
|---|---|---|---|
| SD1 | SDIO_1 | 浮空 | SPI-Compatible 模式不用，1 根数据线够 |

**接好线后再上电**。PDC 是高电平有效的外部掉电输入，不得浮空；本项目不使用软件掉电功能，因此直接接 GND。
数据手册还明确要求单位串行模式下未使用的 `SDIO_3/SYNC_I/O` 接地或保持逻辑0，不能浮空，否则高电平会中断
当前串行通信周期。商家示例也把SDIO3和四个profile输入全部主动输出低电平；本项目没有为这些信号分配MCU引脚，
因此直接接GND获得等效的确定状态。模块上电后，5V 通过板载 LDO 输出 1.8V（DDS 内核）和 3.3V（IO），无需外部提供。

- 两路相位都 0°

### 3.2 异常诊断表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `initialized = 0` | init 失败 | 看 `error_count` 和 `last_hal_status` |
| `error_count > 0` | MCU侧传输流程失败 | 检查固件状态和控制流程 |
| `last_hal_status != 0` | HAL 返回错误码 | 查 HAL 定义（HAL_ERROR=1, HAL_BUSY=2, HAL_TIMEOUT=3） |
| `write_count < 20` | init 或回读前通道选择未完整执行 | 多半是某次 SPI 写失败提前返回 |
| `readback_complete = 0` | 回读SPI事务未完成 | 看 `error_count` 和 `last_hal_status` |
| `readback_mismatch_mask != 0` | AD9959未正确接收配置，或SDO/MISO回读链路错误 | 按下面掩码定位，再用示波器检查CS/SCLK/SD0/SD2 |
| `frequency_tuning_word[0] = 0` | 频率字未写入 | 检查 CFTW0 寄存器地址（0x04） |

### 3.3 验证读回（关键！）

当前诊断固件会在初始化末尾自动完成回读，不需要在 Expressions 里临时调用函数。暂停程序后直接展开
`ad9959_diagnostics`，记录 `readback_complete`、`readback_mismatch_mask` 和三组 `*_readback` 数组即可。

注意：实际 FTW 是 8589935，十六进制是 `0x0083126F`。MSB first 发送顺序是 `[0x00, 0x83, 0x12, 0x6F]`。

`readback_mismatch_mask` 位定义：

- `0x01`：FR1不一致
- `0x02`：CH0 CFR不一致
- `0x04`：CH0 CFTW0不一致
- `0x08`：CH1 CFR不一致
- `0x10`：CH1 CFTW0不一致
- `0x1F`：五项全部不一致，优先怀疑写入未到达芯片或SD2→PE5回读链路

如果读回值是 `0xFF`、全0或无规律：检查模块 `SD2` 到 STM32 `PE5` 的接线，
确认 `SD3/SYNC_I/O` 已接GND，并直接在模块排针处检查SCLK、SD0、SD2的数字波形。
回读一致只能证明数字寄存器配置正确，不能单独证明DAC模拟输出幅度和波形正确。

当前排障固件将 PE5 配置为普通GPIO下拉输入：如果此前全 `0xFF` 的回读在烧录该固件后变成全 `0x00`，
说明 PE5 没有被模块 SD2 主动驱动。此时应断电用蜂鸣档确认 PE5→SD2 导通，并确认 PE6→SD0、
PDC→GND、STM32 GND→模块 GND 均可靠连接。

AD9959上电默认 `CSR[2:1]=00`，这是SDIO_0双向、SDIO_2不使用的双线模式。本工程采用独立MOSI/MISO，
因此驱动选择通道时必须同时写入 `CSR[2:1]=01` 三线模式：CH0写 `0x12`，CH1写 `0x22`。
三线模式下SDIO_0只负责输入，SDIO_2负责输出回读数据。

AD9959复位后片内PLL尚未启用，系统时钟等于25MHz参考时钟，`SYNC_CLK=6.25MHz`、周期约160ns。
数据手册要求IO_UPDATE高脉冲大于一个SYNC_CLK周期；原先8个NOP只有约17ns（即使计入GPIO调用开销也没有
可靠覆盖160ns），可能导致首次FR1不生效并使后续更新全部失效。当前诊断固件将PD4高电平固定保持40ms，
并同步记录PD4的ODR/IDR，既排除脉宽变量，也能区分软件命令、外部钳位和模块接线断点。
参考代码的低—高—低更新顺序、寄存器值及MSB优先写入顺序与本工程一致。

STM32H7硬件SPI路径此前已经降低速率并启用 `MasterKeepIOState`，但FR1仍读回全0。为停止继续修补同一路径，
当前版本只替换传输层：初始化时关闭SPI4，把PE2/PE6改为推挽输出、PE5改为下拉输入，以GPIO严格执行
“SCLK低时设置SD0、SCLK上升沿锁存、MSB优先”的商家例程时序。寄存器内容、CS、RESET、IO_UPDATE和接线均不变。
因此这一版的结论是二选一：GPIO位操作成功则根因在H7硬件SPI/HAL路径；仍读全0则问题位于模块接口、接线或模块本体。

当前临时总线探针每200ms执行一个可观测周期，专门用于消除微秒脉冲可能被漏测的歧义：

- 第一步：PD5/CS先连续保持低电平40ms，此时还没有SCLK；
- 40ms结束时：16个GPIO产生的SCLK，SD0固定发送 `00 12`，随后CS恢复高电平；
- 第二次：32个GPIO产生的SCLK，SD0先发送读指令 `81`，随后SD2应返回 `D0 00 00`；
- Expressions中的 `bus_probe_cs_low_count` 和 `bus_probe_count` 都应持续递增，`bus_probe_last_hal_status` 应为0；
- `bus_probe_signature` 必须为 `0x49555031`（十进制 `1230327857`，ASCII“IUP1”），且 `bitbang_gpio_ready=1`、`bitbang_clock_edges` 持续递增。任一不满足都说明板上程序与当前ELF不一致或初始化尚未执行；
- `bus_probe_cs_low_odr/idr=0/0` 且 `bus_probe_cs_high_odr/idr=1/1` 才表示PD5的输出寄存器和引脚输入电平都随命令变化；
- 若低阶段是 `ODR=0, IDR=1`，说明MCU已经命令拉低但引脚仍被外部顶高、GPIO模式不对或引脚受损；
- 若低阶段仍是 `ODR=1, IDR=1`，说明PD5被其他代码重新拉高或当前板上并未运行此诊断固件。

2026-07-26实板诊断边界：`SYNC_CLK=6.25MHz/3.68Vpp` 已证明AD9959的25MHz参考时钟、
I/O电源和数字内核正在运行，但PLL×20的FR1配置尚未进入活动寄存器；同时模块端SDIO0存在约3.15V跳变，
而IO_UPDATE未观察到有效逻辑脉冲。因此本版只放大并采样IO_UPDATE，不切换传输层或修改寄存器内容。

## 4. 示波器测量

### 4.1 准备

- 探头接 AD9959 CH0 的 IOUT 引脚（模块上标 CH0 或 OUT0）
- 探头地接 AD9959 模块 GND
- 示波器输入阻抗选 1MΩ（不要 50Ω，否则可能影响输出）
- 耦合方式选 AC（去除 DC 偏置）

### 4.2 期望波形

| 项 | 期望值 |
|---|---|
| 波形 | 正弦波 |
| 频率 | 1.000000 MHz ± 0.12 Hz |
| 峰峰值 | 约 0.5-0.8 V（取决于模块输出电路和负载） |
| DC 偏置 | ~0 V（AC 耦合后） |

### 4.3 关键测量点

#### 4.3.1 CH0 输出

- 探头接 CH0 IOUT
- 按 Auto Scale
- 量频率：应显示 1.000 MHz
- 切到 Frequency Counter 模式，分辨率 6 位

#### 4.3.2 CH1 输出

- 探头换到 CH1 IOUT
- 同上，应显示 1.000 MHz

#### 4.3.3 串行时序（可选，用逻辑分析仪）

| 信号 | 探头位置 | 期望 |
|---|---|---|
| SCLK | PE2 | GPIO产生的慢速Mode 0方波，CS拉低期间跳变；不再固定为1.875MHz |
| SDIO_0 | PE6 | 写时按MSB优先字节流变化 |
| SDIO_2 | PE5 | 读时应由模块驱动返回字节流 |
| CS | PD5 | 写寄存器时拉低，写完拉高 |
| IO_UPDATE | PD4 | 每次写寄存器后产生一个上升沿，高电平保持约40ms |

示波器必须使用 **DC耦合、10×探头、模块GND作参考地**。数字信号若显示为约`-2.6V～+0.5V`
但Vpp约3.1V，通常是通道处于AC耦合或垂直偏置不正确，不能据此判断模块真的产生了负电压。

## 5. 功能验证测试

### 5.1 改频率验证

在 Debug 模式下暂停，在 Expressions 里执行：

```c
ad9959_set_frequency(ad9959_channel_0, 5000000u);  // CH0 改 5 MHz
```

预期：
- `ad9959_diagnostics.frequency_hz[0] = 5000000`
- `ad9959_diagnostics.frequency_tuning_word[0] = 42949673`（5M × 2^32 / 500M = 42949672.96，四舍五入 42949673）
- 示波器量 CH0 频率 = 5.000000 MHz

```c
ad9959_set_frequency(ad9959_channel_1, 10000000u);  // CH1 改 10 MHz
```

预期：
- `frequency_hz[1] = 10000000`
- `frequency_tuning_word[1] = 85899346`
- 示波器量 CH1 频率 = 10.000000 MHz

### 5.2 双通道独立性验证

```c
ad9959_set_frequency(ad9959_channel_0, 2000000u);  // CH0 = 2 MHz
ad9959_set_frequency(ad9959_channel_1, 3000000u);  // CH1 = 3 MHz
```

预期：
- CH0 示波器显示 2 MHz
- CH1 示波器显示 3 MHz
- 两个通道完全独立

### 5.3 相位验证

```c
ad9959_set_phase(ad9959_channel_1, 90u);  // CH1 相位 90°
```

预期：
- `phase_degrees[1] = 90`
- `phase_word[1] = 4096`（90 × 16384 / 360 = 4096）
- CH0 和 CH1 一起看（双通道示波器），CH1 应滞后 CH0 1/4 周期

```c
ad9959_set_phase(ad9959_channel_1, 180u);  // CH1 相位 180°
```

预期：
- CH1 相对 CH0 反相（差半个周期）

### 5.4 幅度验证

```c
ad9959_set_amplitude(ad9959_channel_0, 512u);  // CH0 幅度减半
```

预期：
- `amplitude[0] = 512`
- CH0 峰峰值约为原来的一半

```c
ad9959_set_amplitude(ad9959_channel_0, 0u);  // CH0 幅度归零
```

预期：
- CH0 输出为 0（接近 0V）

```c
ad9959_set_amplitude(ad9959_channel_0, 1023u);  // 恢复满量程
```

### 5.5 频率极限验证

测试边界频率：

```c
// 低频
ad9959_set_frequency(ad9959_channel_0, 1u);  // 1 Hz
// 示波器量 CH0 应显示 1 Hz（示波器需切到低频档）

// 高频
ad9959_set_frequency(ad9959_channel_0, 100000000u);  // 100 MHz
// 示波器量 CH0 应显示 100 MHz

// 超限（应拒绝）
ad9959_set_frequency(ad9959_channel_0, 0u);
// 返回 ad9959_status_invalid_frequency，输出不变

ad9959_set_frequency(ad9959_channel_0, 300000000u);  // 300 MHz 超过 200 MHz 上限
// 返回 ad9959_status_invalid_frequency，输出不变
```

## 6. 闭环 PLL 验证（数字锁相环）

如果你已经实现了 FFT 反馈到 DDS 频率修正的闭环逻辑，可以按以下步骤验证 AD9959 是否正确响应：

### 6.1 读回寄存器验证

每次 `ad9959_set_frequency()` 后，立即读回 CFTW0 验证：

```c
ad9959_status_t status = ad9959_set_frequency(ad9959_channel_0, 1234567u);
uint8_t ftw_readback[4] = {0};
ad9959_read_register(0x04u, ftw_readback, 4u);

// 拼接 32 位 FTW
uint32_t ftw_value = ((uint32_t)ftw_readback[0] << 24)
                   | ((uint32_t)ftw_readback[1] << 16)
                   | ((uint32_t)ftw_readback[2] << 8)
                   | (uint32_t)ftw_readback[3];

// 期望 ftw_value == ad9959_diagnostics.frequency_tuning_word[0]
// 期望 ftw_value == 10604850（1234567 × 2^32 / 500M ≈ 10604849.99）
```

如果 `ftw_value` 与 `diagnostics.frequency_tuning_word[0]` 不一致，说明 SPI 通信有问题。

### 6.2 闭环时序

闭环 PLL 工作流程：

1. FFT 测得中频频率 `f_if`
2. 计算 error = `f_if - 100 kHz`
3. 调用 `ad9959_set_frequency(channel, new_freq)` 修正
4. 读回 CFTW0 验证
5. 等下一次 FFT 完成

每次修正约耗时：
- 当前GPIO模拟串行速度由保守延时循环决定，只用于隔离传输层，不作为闭环性能基线；
- `ad9959_set_frequency()` 仍包含两次40ms诊断IO_UPDATE，实板确认寄存器装载和模拟输出恢复后，再恢复硬件SPI并把更新脉宽优化为经过示波器验证的实现。

当前40ms更新脉宽只用于定位故障，不能据此宣称已满足最终闭环实时性要求。

## 7. 故障排查

### 7.1 输出一直是 0V 或 DC

**可能原因**：
1. 模块电源没接好（量 5V 输入和板载 LDO 输出）
2. 25MHz 晶振不振荡
3. RESET 引脚一直拉高（PB4 应该是低电平）
4. CS 一直拉低（PD5 应该是高电平，只有写时才低）
5. FR1 没写入（PLL 未启用，SYSCLK = 0）
6. 输出幅度设为 0
7. PDC 引脚（Power Down Control）被外部拉高导致芯片断电
8. SD3/SYNC_I/O浮空或为高，串行通信周期被中断

**排查步骤**：
1. 量模块 DC 供电座 = 5V
2. 量模块板载 LDO 输出（如有 1V8/3V3 测试点）= 1.8V/3.3V
3. 量 PB4 = 0V（RESET 低）
4. 量 PD5 = 3.3V（CS 高）
5. 量 PD4 = 0V（IO_UPDATE 低）
6. 量模块 PDC = 0V（外部掉电功能关闭）
7. 量模块 SD3 = 0V，并确认P0～P3均固定接GND
8. 调试器看 `initialized = 1`
9. 调试器读回 FR1，应得到 `0xD0 0x00 0x00`（与商家康威科技模块配置一致）
10. 调试器读回 CFTW0，应得到非零值

### 7.2 频率偏差 5 倍（输出 200kHz 而非 1MHz）

**可能原因**：FR1 实际是 4x 倍频（SYSCLK = 100MHz），但代码按 500MHz 计算

**验证**：
- 改 `ad9959_set_frequency(channel, 5000000u)` 期望 5MHz
- 示波器量实际 = 1MHz -> FR1 是 4x（SYSCLK = 100MHz）
- 示波器量实际 = 5MHz -> FR1 是 20x（SYSCLK = 500MHz），代码正确

**如果实测是 4x**：
- 检查 FR1 寄存器值是否为 `0xD0 0x00 0x00`
- 0xD0 对应商家康威科技验证值：20 倍频 + VCO 高范围 + charge pump 75uA 默认

### 7.3 读寄存器返回全 0xFF

**可能原因**：
1. MISO 线（PE5）没接
2. MISO 和 MOSI 接反了
3. SPI 模式错（应为 Mode 0: CPOL=Low, CPHA=1Edge）
4. 读时序错（应为：发指令字节 bit7=1 + 发 dummy 同时读 MISO）

**排查**：
1. 用万用表量 PE5 是否接到 AD9959 SDIO_2（不是 SDIO_0）
2. 示波器看 PE5 在读时是否有信号
3. 临时改成只写不读，看是否能正常输出频率

### 7.4 串行通信间歇性失败

**可能原因**：
1. SCLK/SD0边沿受长线或接触不良影响
2. 接线太长，引入干扰
3. 5V 电源不稳（模块驱动电流峰值 400mA）

**排查**：
1. 当前GPIO模拟串行版先确认 `bitbang_gpio_ready=1` 和 `bitbang_clock_edges` 持续递增
2. 接线缩短到 10cm 以内
3. 5V 电源用独立 1A 适配器，不要从 STM32 USB 5V 分流
4. 示波器分别在MCU引脚和模块排针处测PE2/SCLK、PE6/SD0，比较是否因接线而丢失边沿
5. 模块 GND 与 STM32 GND 必须可靠短接（多根 GND 线并联降低压差）

### 7.5 两通道频率互相影响

**可能原因**：
1. CSR 寄存器没正确切换通道
2. CFR 寄存器被两个通道共享（实际不应该，CFR 是每通道独立的）

**排查**：
1. 读 CSR 寄存器，确认通道位与三线模式位同时存在（CH0=0x12 或 CH1=0x22）
2. 分别读 CH0 和 CH1 的 CFR，应该相同（都是默认值）
3. 分别读 CH0 和 CH1 的 CFTW0，应该是各自写入的值

### 7.6 编译报错 `ad9934_2 not found`

**原因**：之前删 ad9834_2.c/.h 后没有同步 system.h / system.c

**处理**：确认 `system.h` 里没有 `#include "ad9834_2.h"`，`system.c` 里没有 `ad9834_2_init` 调用。

## 9. 后续扩展建议

驱动验证通过后，可以继续：

1. **接入闭环 PLL**：把 `ad9959_set_frequency()` 接入 `dds_control`，让它响应 FFT 反馈
2. **两路独立本振**：CH0 给主本振，CH1 给副本振（外差式两路测量）
3. **相位同步**：用 `ad9959_set_phase()` 实现两路相位锁定（如 90° 正交）
4. **扫频模式**：利用 AD9959 内置 linear sweep，做扫频源（需扩展驱动，写 LSRR/RDW/FDW 寄存器）
5. **多片同步**：用 AD9959 的 SYNC_OUT/SYNC_IN 实现多片同步
