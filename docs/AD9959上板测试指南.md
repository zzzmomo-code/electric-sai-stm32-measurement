**STM32 信号线（本项目实际接法）**

| MCU 引脚 | AD9959 模块丝印 | 芯片引脚名 | 备注 |
|---|---|---|---|
| PE2 | SCLK | SCLK | SPI4 时钟 |
| PE6 | SD0 | SDIO_0 | MOSI（写） |
| PE5 | SD2 | SDIO_2 | MISO（读回） |
| PD4 | UPDATE | I/O_UPDATE | 上升沿刷新寄存器 |
| PD5 | CS | CS | 片选，低有效 |
| PB4 | RST | MASTER_RESET | 硬件复位，高有效 |
| GND | PDC | PWR_DWN_CTL | 必须拉低，禁止芯片进入外部掉电状态 |
| GND | GND | GND | 共地 |

**模块其他引脚（不接，浮空）**

| 模块丝印 | 芯片引脚名 | 处理 | 原因 |
|---|---|---|---|
| SD1 | SDIO_1 | 浮空 | SPI-Compatible 模式不用，1 根数据线够 |
| SD3 | SDIO_3 | 浮空 | 同上 |
| P0, P1, P2, P3 | profile 引脚 | 浮空 | single tone 模式不用，仅 FSK/PSK/ASK 调制用 |

**接好线后再上电**。PDC 是高电平有效的外部掉电输入，不得浮空；本项目不使用软件掉电功能，因此直接接 GND。模块上电后，5V 通过板载 LDO 输出 1.8V（DDS 内核）和 3.3V（IO），无需外部提供。

## 1. 烧录前的硬件自检

### 1.1 不上电，先用万用表查短路

| 测点 | 期望 | 异常处理 |
|---|---|---|
| GND - 5V 输入 | 不通（无穷大电阻） | 短路则检查焊接和电源极性 |
| PE2/PE5/PE6 对 GND | 不通 | 短路则检查 SPI 线 |
| PD4/PD5/PB4 对 GND | 不通 | 短路则检查 GPIO 线 |

### 1.2 上电但不烧录，量电压

**模块供电**：先接好 5V 1A 电源（DC 供电座或 USB），再上电。

| 测点 | 期望值 | 备注 |
|---|---|---|
| 模块 DC 供电座 5V | 5.0 V ± 0.2 V | 输入电源 |
| 模块上 LDO 输出（如有 1V8 测试点） | 1.80 V ± 0.05 V | 板载 LDO 降 |
| 模块上 LDO 输出（如有 3V3 测试点） | 3.30 V ± 0.05 V | 板载 LDO 降 |
| 25MHz 晶振输出端 | 用示波器 AC 耦合看，应有 25MHz 正弦波（峰峰值 ~1V） | 晶振起振 |
| AD9959 各通道 IOUT | 静态时约 0V（未配置） | 上电后未配置前为 0 |

**如果 25MHz 晶振不振荡**：换晶振或换电容（通常 18-22pF）。

⚠️ **不要在模块外部再接 1.8V 或 3.3V 给模块**，模块自带的 LDO 已经处理。除非你拆掉模块的 LDO 改外部供电（不推荐）。

- CH0 输出 1 MHz 正弦波

- 两路相位都 0°
- 两路幅度满量程

## 3. 调试器 Expressions 检查（最先做这一步）

进入 Debug 模式，暂停程序，打开 `Expressions` 窗口，添加以下变量：

### 3.1 关键变量

| 变量名 | 期望值 | 含义 |
|---|---|---|
| `ad9959_diagnostics.initialized` | `1` | 初始化成功 |
| `ad9959_diagnostics.write_count` | `20` | 原初始化写18次，回读前选择CH0/CH1再写CSR各1次 |
| `ad9959_diagnostics.error_count` | `0` | SPI 无错误 |
| `ad9959_diagnostics.last_hal_status` | `0` (HAL_OK) | 最后一次 SPI 返回 OK |
| `ad9959_diagnostics.readback_complete` | `1` | 5项关键寄存器均完成SPI回读 |
| `ad9959_diagnostics.readback_mismatch_mask` | `0` | 5项回读全部与写入值一致 |
| `ad9959_diagnostics.fr1_readback` | `{0xD0,0x00,0x00}` | PLL 20倍频配置已被芯片接收 |
| `ad9959_diagnostics.cfr_readback[0]` | `{0x00,0x03,0x02}` | CH0 单音模式配置已被芯片接收 |
| `ad9959_diagnostics.cfr_readback[1]` | `{0x00,0x03,0x02}` | CH1 单音模式配置已被芯片接收 |
| `ad9959_diagnostics.ftw_readback[0]` | `{0x00,0x83,0x12,0x6F}` | CH0 的1MHz频率字已被芯片接收 |
| `ad9959_diagnostics.ftw_readback[1]` | `{0x00,0x83,0x12,0x6F}` | CH1 的1MHz频率字已被芯片接收 |
| `ad9959_diagnostics.frequency_hz[0]` | `1000000` | CH0 = 1 MHz |
| `ad9959_diagnostics.frequency_hz[1]` | `1000000` | CH1 = 1 MHz |
| `ad9959_diagnostics.frequency_tuning_word[0]` | `8589935` | 1MHz 对应 FTW |
| `ad9959_diagnostics.phase_degrees[0]` | `0` | CH0 相位 0° |
| `ad9959_diagnostics.phase_degrees[1]` | `0` | CH1 相位 0° |
| `ad9959_diagnostics.amplitude[0]` | `1023` | CH0 满量程 |
| `ad9959_diagnostics.amplitude[1]` | `1023` | CH1 满量程 |
| `ad9959_diagnostics.last_channel` | `1` | 最后操作的是 CH1 |

### 3.2 异常诊断表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `initialized = 0` | init 失败 | 看 `error_count` 和 `last_hal_status` |
| `error_count > 0` | SPI 通信失败 | 检查接线、SPI 模式、电源 |
| `last_hal_status != 0` | HAL 返回错误码 | 查 HAL 定义（HAL_ERROR=1, HAL_BUSY=2, HAL_TIMEOUT=3） |
| `write_count < 20` | init 或回读前通道选择未完整执行 | 多半是某次 SPI 写失败提前返回 |
| `readback_complete = 0` | 回读SPI事务未完成 | 看 `error_count` 和 `last_hal_status` |
| `readback_mismatch_mask != 0` | AD9959未正确接收配置，或SDO/MISO回读链路错误 | 按下面掩码定位，再用示波器检查CS/SCLK/SD0/SD2 |
| `frequency_tuning_word[0] = 0` | 频率字未写入 | 检查 CFTW0 寄存器地址（0x04） |

### 3.3 验证读回（关键！）

当前诊断固件会在初始化末尾自动完成回读，不需要在 Expressions 里临时调用函数。暂停程序后直接展开
`ad9959_diagnostics`，记录 `readback_complete`、`readback_mismatch_mask` 和三组 `*_readback` 数组即可。

注意：实际 FTW 是 8589935，十六进制是 `0x0083126F`。MSB first 发送顺序是 `[0x00, 0x83, 0x12, 0x6F]`。

`readback_mismatch_mask` 位定义：

- `0x01`：FR1不一致
- `0x02`：CH0 CFR不一致
- `0x04`：CH0 CFTW0不一致
- `0x08`：CH1 CFR不一致
- `0x10`：CH1 CFTW0不一致
- `0x1F`：五项全部不一致，优先怀疑SPI写入未到达芯片或SD2→MISO回读链路

如果读回值是 `0xFF`、全0或无规律：检查模块 `SD2` 到 STM32 `PE5/SPI4_MISO` 的接线，并检查SPI模式和信号完整性。
回读一致只能证明数字寄存器配置正确，不能单独证明DAC模拟输出幅度和波形正确。

## 4. 示波器测量

### 4.1 准备

- 探头接 AD9959 CH0 的 IOUT 引脚（模块上标 CH0 或 OUT0）
- 探头地接 AD9959 模块 GND
- 示波器输入阻抗选 1MΩ（不要 50Ω，否则可能影响输出）
- 耦合方式选 AC（去除 DC 偏置）

### 4.2 期望波形

| 项 | 期望值 |
|---|---|
| 波形 | 正弦波 |
| 频率 | 1.000000 MHz ± 0.12 Hz |
| 峰峰值 | 约 0.5-0.8 V（取决于模块输出电路和负载） |
| DC 偏置 | ~0 V（AC 耦合后） |

### 4.3 关键测量点

#### 4.3.1 CH0 输出

- 探头接 CH0 IOUT
- 按 Auto Scale
- 量频率：应显示 1.000 MHz
- 切到 Frequency Counter 模式，分辨率 6 位

#### 4.3.2 CH1 输出

- 探头换到 CH1 IOUT
- 同上，应显示 1.000 MHz

#### 4.3.3 SPI 时序（可选，用逻辑分析仪）

| 信号 | 探头位置 | 期望 |
|---|---|---|
| SCLK | PE2 | 1.875 MHz 方波，CS 拉低期间跳变 |
| MOSI | PE6 | 写时按字节流变化 |
| MISO | PE5 | 读时按字节流变化 |
| CS | PD5 | 写寄存器时拉低，写完拉高 |
| IO_UPDATE | PD4 | 每次写寄存器后产生一个上升沿脉冲 |

## 5. 功能验证测试

### 5.1 改频率验证

在 Debug 模式下暂停，在 Expressions 里执行：

```c
ad9959_set_frequency(ad9959_channel_0, 5000000u);  // CH0 改 5 MHz
```

预期：
- `ad9959_diagnostics.frequency_hz[0] = 5000000`
- `ad9959_diagnostics.frequency_tuning_word[0] = 42949673`（5M × 2^32 / 500M = 42949672.96，四舍五入 42949673）
- 示波器量 CH0 频率 = 5.000000 MHz

```c
ad9959_set_frequency(ad9959_channel_1, 10000000u);  // CH1 改 10 MHz
```

预期：
- `frequency_hz[1] = 10000000`
- `frequency_tuning_word[1] = 85899346`
- 示波器量 CH1 频率 = 10.000000 MHz

### 5.2 双通道独立性验证

```c
ad9959_set_frequency(ad9959_channel_0, 2000000u);  // CH0 = 2 MHz
ad9959_set_frequency(ad9959_channel_1, 3000000u);  // CH1 = 3 MHz
```

预期：
- CH0 示波器显示 2 MHz
- CH1 示波器显示 3 MHz
- 两个通道完全独立

### 5.3 相位验证

```c
ad9959_set_phase(ad9959_channel_1, 90u);  // CH1 相位 90°
```

预期：
- `phase_degrees[1] = 90`
- `phase_word[1] = 4096`（90 × 16384 / 360 = 4096）
- CH0 和 CH1 一起看（双通道示波器），CH1 应滞后 CH0 1/4 周期

```c
ad9959_set_phase(ad9959_channel_1, 180u);  // CH1 相位 180°
```

预期：
- CH1 相对 CH0 反相（差半个周期）

### 5.4 幅度验证

```c

```

预期：
- `amplitude[0] = 512`

```c
ad9959_set_amplitude(ad9959_channel_0, 0u);  // CH0 幅度归零
```

预期：
- CH0 输出为 0（接近 0V）

```c

```

### 5.5 频率极限验证

测试边界频率：

```c
// 低频
ad9959_set_frequency(ad9959_channel_0, 1u);  // 1 Hz
// 示波器量 CH0 应显示 1 Hz（示波器需切到低频档）
```

## 6. 闭环 PLL 验证（数字锁相环）

如果你已经实现了 FFT 反馈到 DDS 频率修正的闭环逻辑，可以按以下步骤验证 AD9959 是否正确响应：

### 6.1 读回寄存器验证

每次 `ad9959_set_frequency()` 后，立即读回 CFTW0 验证：

```c
ad9959_status_t status = ad9959_set_frequency(ad9959_channel_0, 1234567u);
uint8_t ftw_readback[4] = {0};
ad9959_read_register(0x04u, ftw_readback, 4u);

// 拼接 32 位 FTW
uint32_t ftw_value = ((uint32_t)ftw_readback[0] << 24)
                   | ((uint32_t)ftw_readback[1] << 16)
                   | ((uint32_t)ftw_readback[2] << 8)
                   | (uint32_t)ftw_readback[3];

// 期望 ftw_value == ad9959_diagnostics.frequency_tuning_word[0]
// 期望 ftw_value == 10604850（1234567 × 2^32 / 500M ≈ 10604849.99）
```

如果 `ftw_value` 与 `diagnostics.frequency_tuning_word[0]` 不一致，说明 SPI 通信有问题。

### 6.2 闭环时序

闭环 PLL 工作流程：

1. FFT 测得中频频率 `f_if`
2. 计算 error = `f_if - 100 kHz`
3. 调用 `ad9959_set_frequency(channel, new_freq)` 修正
4. 读回 CFTW0 验证
5. 等下一次 FFT 完成

每次修正约耗时：
- ad9959_set_frequency 内部：select_channel（CSR指令+1字节，约9us）+ CFTW0写入（指令+4字节，约22us @ 1.875MHz）+ 两次IO_UPDATE
- 总计约 5-10us

满足电赛 600kHz 采样率下的实时性要求。

## 7. 故障排查

### 7.1 输出一直是 0V 或 DC

**可能原因**：
1. 模块电源没接好（量 5V 输入和板载 LDO 输出）
2. 25MHz 晶振不振荡
3. RESET 引脚一直拉高（PB4 应该是低电平）
4. CS 一直拉低（PD5 应该是高电平，只有写时才低）
5. FR1 没写入（PLL 未启用，SYSCLK = 0）
6. 输出幅度设为 0
7. PDC 引脚（Power Down Control）被外部拉高导致芯片断电

**排查步骤**：
1. 量模块 DC 供电座 = 5V
2. 量模块板载 LDO 输出（如有 1V8/3V3 测试点）= 1.8V/3.3V
3. 量 PB4 = 0V（RESET 低）
4. 量 PD5 = 3.3V（CS 高）
5. 量 PD4 = 0V（IO_UPDATE 低）
6. 量模块 PDC = 0V（外部掉电功能关闭）
7. 调试器看 `initialized = 1`
8. 调试器读回 FR1，应得到 `0xD0 0x00 0x00`（与商家康威科技模块配置一致）
9. 调试器读回 CFTW0，应得到非零值

### 7.2 频率偏差 5 倍（输出 200kHz 而非 1MHz）

**可能原因**：FR1 实际是 4x 倍频（SYSCLK = 100MHz），但代码按 500MHz 计算

**验证**：
- 改 `ad9959_set_frequency(channel, 5000000u)` 期望 5MHz
- 示波器量实际 = 1MHz -> FR1 是 4x（SYSCLK = 100MHz）
- 示波器量实际 = 5MHz -> FR1 是 20x（SYSCLK = 500MHz），代码正确

**如果实测是 4x**：
- 检查 FR1 寄存器值是否为 `0xD0 0x00 0x00`
- 0xD0 对应商家康威科技验证值：20 倍频 + VCO 高范围 + charge pump 75uA 默认

### 7.3 读寄存器返回全 0xFF

**可能原因**：
1. MISO 线（PE5）没接
2. MISO 和 MOSI 接反了
3. SPI 模式错（应为 Mode 0: CPOL=Low, CPHA=1Edge）
4. 读时序错（应为：发指令字节 bit7=1 + 发 dummy 同时读 MISO）

**排查**：
1. 用万用表量 PE5 是否接到 AD9959 SDIO_2（不是 SDIO_0）
2. 示波器看 PE5 在读时是否有信号
3. 临时改成只写不读，看是否能正常输出频率

### 7.4 SPI 通信间歇性失败

**可能原因**：
1. SPI SCLK 引脚（PE2）速度太低
2. 接线太长，引入干扰
3. 5V 电源不稳（模块驱动电流峰值 400mA）

**排查**：
1. 检查 .ioc 里 PE2/PE5/PE6 的 GPIO_Speed = VERY_HIGH（已配置）
2. 接线缩短到 10cm 以内
3. 5V 电源用独立 1A 适配器，不要从 STM32 USB 5V 分流
4. 降低 SCLK 频率（改 BaudRatePrescaler=16 -> 7.5MHz）
5. 模块 GND 与 STM32 GND 必须可靠短接（多根 GND 线并联降低压差）

### 7.5 两通道频率互相影响

**可能原因**：
1. CSR 寄存器没正确切换通道
2. CFR 寄存器被两个通道共享（实际不应该，CFR 是每通道独立的）

**排查**：
1. 读 CSR 寄存器，确认只有一位为 1（CH0=0x10 或 CH1=0x20）
2. 分别读 CH0 和 CH1 的 CFR，应该相同（都是默认值）
3. 分别读 CH0 和 CH1 的 CFTW0，应该是各自写入的值

### 7.6 编译报错 `ad9934_2 not found`

**原因**：之前删 ad9834_2.c/.h 后没有同步 system.h / system.c

**处理**：确认 `system.h` 里没有 `#include "ad9834_2.h"`，`system.c` 里没有 `ad9834_2_init` 调用。

## 9. 后续扩展建议

驱动验证通过后，可以继续：

1. **接入闭环 PLL**：把 `ad9959_set_frequency()` 接入 `dds_control`，让它响应 FFT 反馈
2. **两路独立本振**：CH0 给主本振，CH1 给副本振（外差式两路测量）
3. **相位同步**：用 `ad9959_set_phase()` 实现两路相位锁定（如 90° 正交）
4. **扫频模式**：利用 AD9959 内置 linear sweep，做扫频源（需扩展驱动，写 LSRR/RDW/FDW 寄存器）
5. **多片同步**：用 AD9959 的 SYNC_OUT/SYNC_IN 实现多片同步

## 附：调试快速命令

进入 Debug 模式后，在 Expressions 窗口添加这些常用表达式：

```c
ad9959_diagnostics.initialized           // 是否初始化成功
ad9959_diagnostics.error_count           // SPI 错误数
ad9959_diagnostics.write_count           // 成功写次数
ad9959_diagnostics.last_hal_status       // 最近 HAL 返回值
ad9959_diagnostics.readback_complete     // 初始化自动回读是否完成
ad9959_diagnostics.readback_mismatch_mask // 关键寄存器回读不一致掩码，期望0
ad9959_diagnostics.fr1_readback          // 期望 D0 00 00
ad9959_diagnostics.cfr_readback          // 两通道均期望 00 03 02
ad9959_diagnostics.ftw_readback          // 两通道均期望 00 83 12 6F
ad9959_diagnostics.frequency_hz[0]       // CH0 当前频率
ad9959_diagnostics.frequency_hz[1]       // CH1 当前频率
ad9959_diagnostics.phase_degrees[0]     // CH0 相位
ad9959_diagnostics.amplitude[0]          // CH0 幅度
ad9959_diagnostics.last_channel          // 最近操作通道
```

需要测试某个 API 时，直接在 Expressions 输入：

```c
ad9959_set_frequency(ad9959_channel_0, 5000000u)
ad9959_set_phase(ad9959_channel_1, 90u)
ad9959_set_amplitude(ad9959_channel_0, 512u)
```

Expressions 调用会立即执行，示波器同步观察输出变化。
