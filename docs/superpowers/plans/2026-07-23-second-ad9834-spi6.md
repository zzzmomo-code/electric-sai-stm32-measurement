# SPI6 Second AD9834 Driver Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independently initialized second AD9834 driver on SPI6, preserve the first driver's alternating-register behavior under a lowercase API, and initialize the second device to 900 kHz.

**Architecture:** Keep the existing SPI2 driver isolated and add `ad9834_2.c/.h` with its own types, diagnostics, SPI6 transport, GPIO controls, hardware reset handling, and alternating-register state. Integrate only the second driver's initialization through `system_init()`; no main-loop processing or `dds_control` coupling is added.

**Tech Stack:** STM32H743 HAL C, STM32CubeIDE 1.19.0, AD9834 16-bit serial protocol, Python `unittest` contract/host tests, generated Debug Make build.

## Global Constraints

- All new user `.c/.h` files must be under `Core/User/`; every user `.c` includes only `system.h`.
- Do not modify `.ioc`, CubeMX-generated initialization code, GPIO, DMA, NVIC, clocks, or interrupt callbacks.
- SPI6 is already configured as master transmit-only, 16-bit, MSB-first, CPOL high, first-edge sampling, software NSS, 30 Mbit/s.
- Second-device mapping is PB3/SPI6_SCK, PB5/SPI6_MOSI, PD5/DDS2_FSYNC, PD6/DDS2_FS, PD7/DDS2_PS, and PB4/DDS2_RST.
- Both AD9834 devices use a 75 MHz MCLK and permit output frequencies from 1 Hz through 30 MHz.
- Rename the user's uncommitted `DDS_SetFrequency()` to `dds_set_frequency()` without changing its alternating-register behavior.
- Use lowercase snake case for all user-defined identifiers and complete Chinese module/function/variable comments before delivery.
- Preserve all unrelated working-tree changes; stage and commit only files belonging to the current task.
- Do not stage Debug artifacts and do not push without explicit user permission.


Implement rounded 75 MHz tuning-word calculation with 64-bit arithmetic.

- [ ] **Step 4: Implement register setters and selectors**

Mirror the validated first-driver semantics with second-prefixed types and diagnostics:

- reject invalid register enums before GPIO/SPI;
- reject frequency 0 or above 30 MHz;
- reject phase above 359 degrees;
- send low then high 14-bit frequency words;
- update diagnostics only after the complete logical operation succeeds;
- map FREQ0/FREQ1 to PD6 low/high and PHASE0/PHASE1 to PD7 low/high.

- [ ] **Step 5: Implement reset-safe initialization**

Clear all diagnostics and set deterministic pins. Raise PB4/RESET before sending control/register words. On success, send RUN, lower RESET, select FREQ0/PHASE0, reset the alternating active-register state to FREQ0, and set `initialized = 1u`.

Use a single failure path that explicitly restores FSYNC high and leaves RESET high:

```c
static ad9834_2_status_t ad9834_2_init_fail(ad9834_2_status_t status)
{
    HAL_GPIO_WritePin(DDS2_FSYNC_GPIO_Port, DDS2_FSYNC_Pin, GPIO_PIN_SET);
    HAL_GPIO_WritePin(DDS2_RST_GPIO_Port, DDS2_RST_Pin, GPIO_PIN_SET);
    return status;
}
```

- [ ] **Step 6: Implement the second alternating update**

Use a static active register initialized to FREQ0. `dds2_set_frequency()` computes the inactive register, writes it with `ad9834_2_set_frequency_register_hz()`, and changes PD6 only after success. Update the active state only after selection.
