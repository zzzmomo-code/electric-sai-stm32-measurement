## 第一部分：系统是什么

### 1.1 一句话概括

**STM32H743VIT6 + AD9834 + AD835 + VCA824 + 片上 ADC + 淘晶驰串口屏**，组成外差式幅频测量装置。

### 1.2 数据流

```
被测信号 fin (1-30 MHz)
  ↓
过零比较器整形成方波
  ↓
TIM5 粗测 fin（PA0，TIM5_CH1）
  ↓
DDS 初始本振 fLO = fin - 100 kHz（AD9834 输出）
  ↓
AD835 混频（fin × fLO）
  ↓
模拟低通滤波 → 中频 fif
  ↓
ADC1/ADC2 双重同步采样（600 kSPS，PC4+PB1）
  ↓
65536 点 F32 FFT（CMSIS-DSP）
  ↓
测量频率、幅度、相位、THD、波形
  ↓
串口屏显示 + 5 次闭环修正 DDS
```

### 1.3 闭环追频逻辑

低侧本振方案：`fADC = fin - fDDS`

- 若 `fADC > 100 kHz` → DDS 太低 → `DDS_new = DDS_old + error`
- 若 `fADC < 100 kHz` → DDS 太高 → `DDS_new = DDS_old + error`（error 为负）
- 若 `fADC = 100 kHz` → DDS 正确 → 不修正

5 次成功修正后进入 holding 状态，DDS 固定。

## 第二部分：硬件接线

### 2.1 完整引脚映射

| MCU 引脚 | 外设 | 连接 | 用途 |
|---|---|---|---|
| PA0 | TIM5_CH1 | 过零比较器输出 | 粗测输入频率（1-30 MHz） |
| PA4 | DAC1_OUT1 | VGA 控制脚 | 六档电压输出 0~3.3V |
| PC4 | ADC1_INP4 | CH1 模拟输入 | 主信号采集 |
| PB1 | ADC2_INP5 | CH2 模拟输入 | 参考信号采集 |
| PB12 | GPIO_Output | AD9834 FSYNC | SPI 片选（低有效） |
| PB13 | SPI2_SCK | AD9834 SCLK | SPI 时钟 8 MHz |
| PB15 | SPI2_MOSI | AD9834 SDATA | SPI 数据 |
| PB14 | GPIO_Output | AD9834 FSELECT | 频率寄存器选择（0=FREQ0） |
| PD8 | GPIO_Output | AD9834 PSELECT | 相位寄存器选择（0=PHASE0） |
| PA9 | USART1_TX | 串口屏 RX | HMI 数据发送 |
| PA10 | USART1_RX | 串口屏 TX | HMI 命令接收 |

**必须共地**：MCU、比较器、AD9834、模拟前端、VGA、串口屏全部共地。

### 2.2 供电要求

- MCU：3.3V（通过 ST-LINK 或外部 LDO）
- AD9834：AVDD=5V, DVDD=3.3V（或统一 3.3V，看模块）
- AD835：±5V 双电源
- VCA824：±5V 双电源
- 串口屏：5V/500mA 独立供电（建议不接 MCU 的 5V，避免电流冲击）

### 2.3 信号安全

- PA0 输入必须 0~3.3V 方波，超过会损坏 MCU
- PC4、PB1 模拟输入必须 VSSA~VDDA 范围（约 0~3.3V），超过用限幅二极管保护
- AD835 输入 ±1V，超过会削顶
- VCA824 输入 ±1V（差分），输出 ±2.5V

## 第四部分：操作流程

### 4.1 上电初始化（自动）

1. MCU 上电 → `system_init()` 自动执行
2. VGA 设为第 0 档（最安全，增益最小）
3. AD9834 初始化为 100 kHz 测试输出（等待第一次 M 命令）
4. ADC、FFT、HMI 模块启动
5. 串口屏显示 `WAIT` 状态

### 4.2 接入信号

1. 接好 PA0 方波输入（1~30 MHz 范围内）
2. 接好 PC4、PB1 模拟输入（混频后中频信号）
3. 串口屏应自动显示 TIM5 粗测频率

### 4.3 触发追频（M 命令）

**方法 A**：在串口屏上按 `M` 按键
**方法 B**：从 PC 通过 USB-TTL 发送字节 `0x4D`

触发后：
1. 状态变 `EST`（估计中）
2. TIM5 粗测 → DDS 设为 `fin - 100 kHz`
3. 5 次 ADC 闭环修正（每次约 110 ms，因为 65536/600k ≈ 109 ms）
4. 状态变 `LOCK`（锁定）
5. DDS 固定在最终频率

### 4.4 切换 VGA 档位

按串口屏 `0`~`5` 按键：
- `0`：最小增益（约 0.014 倍）
- `5`：最大增益（约 2.04 倍）

档位选择立即生效，不需要重新追频。

### 4.5 重新追频

任何时候按 `M` 都可以重新开始追频：
- 状态机清零
- 重新粗调
- 重新 5 次补偿

### 4.6 串口屏显示内容

| 控件名 | 显示 |
|---|---|
| `t_timer_freq` | TIM5 粗测输入频率 |
| `t_adc_freq` | ADC/FFT 中频 |
| `t_adc_amp` | ADC CH1 峰峰值 |
| `t_real_freq` | 换算后的被测频率（DDS + ADC） |
| `t_real_amp` | 换算后的被测幅度（Vpp / VGA 增益） |
| `t_wave` | SINE / SQUARE / TRIANGLE / UNKNOWN |
| `t_dds_freq` | AD9834 当前输出频率 |
| `t_vga` | 当前 VGA 档位 |
| `t_status` | WAIT / EST / LOCK / CLIP / ERROR |
| `t_overflow` | ADC DMA 溢出计数 |

## 第五部分：代码思路与实现

### 5.1 整体架构

```
main.c (CubeMX 生成，用户区只调 system_init/process)
  ↓
system.c (用户入口，统一调度)
  ├─ vga_control_init/process
  ├─ measurement_result_init
  ├─ measurement_fft_init
  ├─ frequency_measure_init
  ├─ dds_control_init/process  ← 新增 5 次闭环补偿
  ├─ hmi_tjc_init/process      ← 新增 M 命令
  ├─ adc_dual_init/process
  └─ measurement_conversion    ← 新增集中换算
```

### 5.2 模块职责和调用顺序

`system_process()` 主循环执行顺序（system.c:112-124）：

```c
void system_process(void)
{
    hmi_tjc_process_input();       // 1. 消费串口屏命令（0~5, M）
    frequency_measure_process();   // 2. TIM5 粗测更新
    dds_control_process();         // 3. DDS 闭环补偿状态机
    adc_dual_process();            // 4. 同步 DMA 采样标志
    measurement_fft_process();    // 5. 65536 点 FFT + 测量计算
    adc_dual_process();            // 6. 二次同步（不重复处理）
    if (measurement_fft_hmi_refresh_allowed())
    {
        hmi_tjc_process();         // 7. 仅在 FFT 空档刷屏
    }
}
```

**为什么这个顺序**：
- HMI 输入最先处理，保证按键响应
- FFT 期间不刷屏（9600 波特率会破坏连续采样窗口）
- 二次 `adc_dual_process()` 只同步 TIM2 启停状态，不重复处理 DMA 标志

### 5.3 自动追频状态机（dds_control.c）

#### 状态定义

```c
typedef enum {
    dds_control_state_waiting = 0,      // 等待 M 命令
    dds_control_state_test,             // 固定测试模式
    dds_control_state_coarse,           // 粗调中
    dds_control_state_compensating,     // 5 次补偿中
    dds_control_state_holding,          // 5 次后保持
    dds_control_state_error             // 错误
} dds_control_state_t;
```

#### 状态转移图

```
       M 按键
waiting ───────► coarse ───粗调成功──► compensating
   ↑              │                        │
   │              │粗调失败                │5 次成功
   │              ▼                        ▼
   │            error                  holding
   │                                      │
   │             M 按键                    │
   └──────────────────────────────────────┘
                  (重新开始)
```

#### 关键代码片段（dds_control.c:134-181）

```c
static uint8_t dds_control_apply_adc_compensation(void)
{
    measurement_result_t result;
    // 1. 只消费新的、有效的 FFT 帧（用 sequence 去重）
    if ((measurement_result_get_snapshot(&result) == 0u)
        || (result.valid == 0u)
        || ((result.valid_mask & MEASUREMENT_VALID_FREQUENCY) == 0u)
        || (!isfinite(result.frequency_hz))
        || (result.frequency_hz <= 0.0f)
        || (result.sequence == dds_control_diagnostics.last_result_sequence))
    {
        return 0u;
    }

    // 2. 记录 sequence 避免重复消费
    dds_control_diagnostics.last_result_sequence = result.sequence;
    dds_control_diagnostics.adc_frequency_hz = result.frequency_hz;
    
    // 3. 误差 = 当前中频 - 目标 100 kHz
    dds_control_diagnostics.frequency_error_hz = (int32_t)lroundf(
        result.frequency_hz - (float)DDS_CONTROL_TARGET_IF_HZ);
    
    // 4. DDS_new = DDS_old + error（低侧本振）
    desired_output_hz = (int64_t)dds_control_diagnostics.output_frequency_hz
                        + (int64_t)dds_control_diagnostics.frequency_error_hz;
    
    // 5. 范围检查 + 写入
    if ((desired_output_hz < 1) || (desired_output_hz > (int64_t)AD9834_MAX_OUTPUT_HZ))
    {
        dds_control_diagnostics.error_count++;
        dds_control_diagnostics.state = dds_control_state_error;
        return 0u;
    }
    if (dds_control_apply_output(...) == 0u) return 0u;
    
    // 6. 计数 + 重同步 FFT 窗口
    dds_control_diagnostics.compensation_count++;
    if (dds_control_diagnostics.compensation_count >= DDS_CONTROL_COMPENSATION_LIMIT)
    {
        dds_control_diagnostics.state = dds_control_state_holding;
    }
    else
    {
        measurement_fft_resynchronize();  // 避免调整前后的样本混入
    }
    return 1u;
}
```

### 5.4 AD9834 双寄存器设计思路

#### 为什么需要双寄存器

AD9834 硬件支持两组频率和相位寄存器，可以在 `FSELECT`/`PSELECT` 引脚电平变化时**瞬间切换**，不会出现毛刺。适合：
- FSK（频移键控）：两个频率快速切换
- BPSK（相移键控）：两个相位快速切换
- 跳频通信

#### 软件设计

```c
// 写寄存器（不改变引脚）
ad9834_set_frequency_register_hz(ad9834_frequency_register_1, 2000000u);
// 切换引脚（不写 SPI）
ad9834_select_frequency_register(ad9834_frequency_register_1);
```

这两个操作分离，让用户可以"先写好备用，再瞬间切换"。

#### 诊断结构扩展

```c
typedef struct {
    // ... 原有字段
    uint32_t frequency_hz[2];           // FREQ0 和 FREQ1 频率
    uint32_t frequency_tuning_word[2];  // 28 位频率字
    uint16_t phase_degrees[2];          // PHASE0 和 PHASE1 角度
    uint16_t phase_word[2];             // 12 位相位字
    uint8_t selected_frequency_register; // 当前 FSELECT 选择
    uint8_t selected_phase_register;    // 当前 PSELECT 选择
    uint8_t last_frequency_register;    // 最近写入的寄存器
    uint8_t last_phase_register;
} ad9834_diagnostics_t;
```

### 5.5 VGA 实测电压模型思路

#### 为什么区分指令电压和实测电压

DAC 输出 `V_DAC = (code / 4095) × VDDA`，但 VDDA 不是精确 3.3V（可能是 3.27V 或 3.33V），且 DAC 有失调、负载效应。**指令电压和实测电压有差异**。

#### 设计

- `VGA_CONTROL_LEVEL_*_VOLTAGE_V`：指令电压（0/0.66/1.32/1.98/2.64/3.30），只用来生成 12 位 DAC 码
- `VGA_CONTROL_LEVEL_*_MEASURED_VOLTAGE_V`：PA4 对地实测电压，用于 VG 和 AV 计算

**标定时只改实测电压宏，不改指令电压宏**，这样 DAC 码不变，但 VG/AV 模型用的是真实电压。

#### 公式

```c
#define VGA_CONTROL_VG_FROM_DAC_VOLTAGE(dac_voltage_v) \
    ((VGA_CONTROL_VG_SCALE * (dac_voltage_v)) + VGA_CONTROL_VG_OFFSET_V)
// VG = (20/33) × V_DAC - 1

#define VGA_CONTROL_GAIN_FROM_VG(vg_voltage_v) \
    (((1.0f + (vg_voltage_v)) * VGA_CONTROL_RF) / VGA_CONTROL_RG)
// AV = (1 + VG) × Rf / RG
```

### 5.6 measurement_conversion 集中化思路

#### 为什么集中

旧版频率换算 `f_real = f_DDS + f_ADC` 散落在 HMI 里。如果要做频响拟合（例如修正 DDS 时钟误差），公式会散落在多处，难以维护。

#### 设计

```c
// measurement_conversion.c
float measurement_conversion_frequency_hz(
    float timer_frequency_hz,   // TIM5 粗测（后备）
    float dds_frequency_hz,     // DDS 当前频率
    float adc_frequency_hz)     // ADC 中频
{
    if (dds_and_adc_both_valid)
        return dds_frequency_hz + adc_frequency_hz;
    return timer_frequency_hz;
}

float measurement_conversion_amplitude_vpp(
    float adc_amplitude_vpp,     // ADC 测得 Vpp
    uint8_t vga_level)           // 当前 VGA 档位
{
    float gain;
    if (vga_control_gain_from_level(vga_level, &gain) == ok && gain > 0.01f)
        return adc_amplitude_vpp / gain;
    return adc_amplitude_vpp;
}
```

后续要加频响拟合，只改这两个函数。

### 5.7 HMI M 命令处理思路

#### 接收设计

USART1 使用**单字节中断接收**（不是 DMA）：
- `HAL_UART_Receive_IT()` 每次启动接收 1 字节
- 回调里保存字节 + 置接收标志
- 主循环 `hmi_tjc_process_input()` 消费命令

为什么不用 DMA？因为命令是单字节，DMA 反而开销大。

#### 命令处理（hmi_tjc.c）

```c
if (command >= '0' && command <= '5') {
    vga_control_set_level(command - '0');
} else if (command == 'M' || command == 'm') {
    frequency_measure_request_now();      // 请求 TIM5 立即测频
    dds_control_request_compensation();   // 请求 5 次闭环补偿
}
```

#### 为什么"请求"而不是直接执行

ISR 要短（<10 μs），不能在 ISR 里：
- 读 TIM5 计数器（需要锁）
- 写 DDS（SPI 阻塞）
- 修改状态机

所以 ISR 只置标志，主循环消费。这是嵌入式铁律。

### 5.8 FFT 重同步思路

每次 DDS 更新后，FFT 窗口里可能混入"DDS 调整前"和"调整后"的样本，导致中频测量错误。

```c
measurement_fft_resynchronize();
```

这个函数让 FFT 丢弃当前半满的缓冲区，从下一个满缓冲区重新开始。保证每次 FFT 都是"DDS 调整后"的纯样本。

## 第八部分：标定流程

### 8.1 ADC 电压标定

```c
// system.c:88-103
measurement_fft_calibration_t ch1_calibration = {
    .volts_per_code = 0.00005035400390625f,  // V/code
    .offset_v = 0.0f,
    .valid = 1u
};
measurement_fft_set_calibration(0u, &ch1_calibration);
```

标定方法：
1. CH1 接已知直流电压 V1（如 1.000V），记录平均 ADC 原始码 C1
2. CH1 接已知直流电压 V2（如 2.000V），记录平均 ADC 原始码 C2
3. 计算：
   - `volts_per_code = (V2 - V1) / (C2 - C1)`
   - `offset_v = V1 - C1 × volts_per_code`
4. 改 `system.c` 里的两个值，重新编译

### 8.2 PA4 VGA 标定

## 第九部分：常见问题

### Q1：为什么 5 次补偿就停？

A：5 次后 DDS 已经稳定在 `fin - 100 kHz` 附近，继续补偿只会抖动。`holding` 状态让 DDS 固定，避免频繁切换破坏测量。要重新追频按 M。

### Q2：为什么用低侧本振（fLO = fin - 100k）而不是高侧（fLO = fin + 100k）？

A：低侧本振下 `fADC = fin - fLO`，修正方向简单：`DDS_new = DDS_old + error`。高侧本振会反转，需要 `DDS_new = DDS_old - error`，容易写错。

### Q3：为什么 USART1 是 9600 而不是 115200？

A：淘晶驰 TJC4827T143_011R_I_P20 屏幕默认 9600，且 9600 在 8 MHz HSI 下误差小。115200 需要更高精度时钟。9600 刷新 10 控件约需 500 ms，够用。

### Q4：为什么 FFT 期间不刷屏？

A：9600 波特率发送一帧约需 200~500 ms，期间 ADC DMA 会积累大量样本。如果同时刷屏，采样窗口会出现缺口，FFT 结果错误。所以 `measurement_fft_hmi_refresh_allowed()` 在 FFT 完成后才放行 HMI。

### Q5：双寄存器 API 实现了但自动追频还是用 FREQ0，为什么？

A：自动追频只需要"写入新频率"这一个操作，不需要"瞬间切换两个频率"。双寄存器 API 是为后续 FSK/BPSK 应用准备的，当前追频用 FREQ0 足够。

### Q6：为什么 Rf 和 RG 默认是 1.0？

A：VCA824 实际 Rf 和 RG 需要根据板子焊接的电阻值填入。当前 1.0 只是占位，上板后必须改成真实值（用万用表测）。

## 附录：Codex 写代码思路学习

### A.1 Codex 的工程纪律

观察队友（Codex）代码，可以总结几条值得学习的工程纪律：

1. **严格分层**：每个模块有明确职责，.h 只暴露接口，.c 实现细节私有化
2. **Doxygen 注释**：每个 .h 开头有文件描述、模块用途、GPIO 映射、依赖外设、初始化方法、调用方法
3. **诊断结构**：每个模块都有 `*_diagnostics_t` 结构，便于调试器直接观察
4. **错误码**：所有公开函数返回状态枚举（`*_status_ok` / `*_status_invalid_*` / `*_status_*_error`）
5. **不破坏 CubeMX 生成**：用户代码只在 `USER CODE BEGIN/END` 区，不碰 `MX_*_Init()`
6. **ISR 短**：中断只置标志，业务逻辑在主循环
7. **范围检查**：所有外部输入先检查范围，再使用
8. **状态机**：复杂流程（如追频）用状态机，不用 if-else 堆叠
9. **去重机制**：用 sequence 序号去重 FFT 帧，避免重复消费
10. **重同步**：每次参数变化后重新同步 FFT 窗口

### A.2 命名约定

- 模块前缀：`vga_control_*` / `dds_control_*` / `ad9834_*`
- 类型后缀：`_t`（如 `dds_control_state_t`）
- 宏全大写：`DDS_CONTROL_COMPENSATION_LIMIT`
- 诊断变量：`*_diagnostics`（如 `dds_control_diagnostics`）
- 状态枚举值：`<module>_state_<state>`（如 `dds_control_state_holding`）

### A.3 测试先行

队友用 Python 写了大量契约测试（`tests/test_*.py`），每个模块都有对应测试：
- `test_ad9834_contract.py` 测 AD9834 头文件和源码必须包含的字符串
- `test_dds_contract.py` 测 DDS 状态机必须的状态、函数、数学方向
- `test_hmi_tjc_contract.py` 测 HMI 协议

这种"契约测试"不运行代码，只检查源码结构。保证重构时不会偷偷改掉关键宏、函数签名、状态名。

### A.4 文档驱动

队友每个模块的 .h 文件开头都有 6 行固定注释：
1. 文件名
2. 一句话描述
3. 模块用途
4. GPIO 引脚映射
5. 依赖的外设和 CubeIDE 配置
6. 初始化和调用方法

这种风格让任何人打开 .h 就能快速理解模块定位，不用读实现。

### A.5 增量演进

从 git log 可以看到队友的开发节奏：

每一步都有独立 commit，每一步都有测试。这种"小步快跑"比"一次写完"更稳。
